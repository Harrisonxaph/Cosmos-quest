# Architecture

Cosmos Quest is a static Vite app written in plain JavaScript modules, with no framework, server or accounts. GitHub Pages hosts the built `dist/` folder.

## Rendering library

Stage 2 adopted **Three.js 0.180.0** (MIT licence), pinned exactly in `package.json`. It is the standard WebGL library, works in mobile browsers and is already used in the owner's other projects. `OrbitControls` from the Three.js add-ons provides drag-to-rotate and pinch or scroll zoom.

## Folders

| Folder | Owns | Rules |
| --- | --- | --- |
| `src/data/` | Scientific content: `planets.json`, `sun.json`, `sources.json`, `quiz.json`, `missions.json`, `experiments.json`, `galaxies.json` (the Cosmos collection, not yet shown in the app) and their schemas | Every value cites a source listed in `sources.json` and `docs/SCIENCE.md`. No presentation settings. |
| `src/utils/` | Pure helpers: formatting, Earth comparisons (`compare.js`), illustrative scale (`scale.js`), panel and facts-card content (`panelContent.js`), label placement and tap picking (`labelLayout.js`) | No DOM, no Three.js, so everything can be tested in Node. |
| `src/features/` | User capabilities: `navigation.js` (pure state machine, URL hash and keyboard map), `quiz.js` (pure quiz state, round picking and scoring), `missions.js` (pure mission progress and completion rules), `experiments.js` (pure experiment settings and results) and `explorer.js` (wires state, panels, quiz, controls and the scene) | Navigation rules live in `navigation.js`, not in event handlers. |
| `src/components/` | Reusable UI: information panel, quiz panel, mission panel and mission bar, experiment panel, facts card (`sceneCard.js`), world selector, Stage 1 planet list, DOM helper | Text is set with `textContent` only. Components do not import Three.js. |
| `src/scenes/` | 3D: `solarSystemScene.js` (scene, camera flights, picking, labels, cleanup), `proceduralTextures.js`, `appearance.js` | Only this folder imports Three.js. `appearance.js` holds illustrative looks, never science. |
| `src/hooks/` | Reserved for a future hook-based UI framework | None is used yet. |

## How it fits together

1. `main.js` loads the data and calls `startExplorer`.
2. `explorer.js` creates the navigation store and renders the panel, selector and planet list straight away, so facts appear before any 3D code downloads.
3. If WebGL is available (and the URL doesn't say `?view=2d`), `explorer.js` dynamically imports `scenes/solarSystemScene.js`. Vite puts Three.js in that separate chunk, so the first page load needs well under 100 kB of app code and the facts appear before the 3D scene arrives.
4. Every user action (button, keyboard shortcut, tap in the scene, Stage 1 "Explore" button, browser Back) dispatches an action to the navigation store. One listener updates the panel, controls, URL hash and scene, so they never disagree.
5. The Planet Quiz is a third panel view (`#/quiz`) beside the overview and world panels, so it needs no 3D. See "Planet Quiz" below. Discovery Missions are a fourth view (`#/missions`) and Science Experiments a fifth (`#/experiments`); see their sections below.
6. If WebGL is missing, the scene fails to load or the graphics context is lost, the scene area shows a message and the 3D-only controls hide. The panels, selector and planet list keep working.

## Planet Quiz

- **Questions** (`src/data/quiz.json`): each has an id, the world it is about, three answers with stable ids, the correct answer id, an explanation and source ids. A `basis` names what supports the answer: an exact fact, a phrase in a panel's summary or composition, a measured value, or a ranking across the planets (for example the smallest distance from the Sun). Tests check each basis against `src/data/` and require the sources to be ones the information panels already cite.
- **Independent answer key** (`tests/data/quiz-answer-key.js`): a hand-written list of the right answer for every question, with the evidence the app must show. It never reads `quiz.json`, so changing a correct answer in the data fails the tests. `tests/data/quiz-checks.js` compares each designated answer with the key, the measured data or ranking, its supporting text and its explanation; mutation tests mark every wrong answer correct, for every question type, and expect a failure. Browser tests also pick answers from the key and check the app's verdict.
- **State and scoring** (`src/features/quiz.js`): a pure reducer with `idle → question → feedback → … → results`. A round picks five different questions, preferring a different world for each and avoiding questions already seen this visit while fresh ones remain. Answers are shuffled, but correctness compares answer ids, so shuffling cannot change it. A second answer or skipping ahead is ignored. Feedback headings and result messages are always encouraging.
- **Panel** (`src/components/quizPanel.js`): renders the state only. Correct and chosen answers are labelled in words and with ✓ symbols, plus border style, not colour alone. Each screen marks one heading with `data-focus-target`; after starting, answering, moving on or finishing, `explorer.js` moves focus there. After an answer, the focused heading's accessible name includes the verdict and the correct answer ("Good try! You chose Oxygen. The correct answer is Nitrogen."), and the explanation is then read through the page's polite live region. The results message is announced the same way.
- **Exploring mid-quiz:** every unanswered question has a visible "Back to exploring" button (as well as Escape) that keeps the child's place. "Explore this planet" selects that world in the normal explorer. The quiz store keeps its state in memory, and every other panel shows a "Back to the quiz" bar until the round is finished or reset. The header button also shows the current question. While the quiz is showing, explorer keyboard shortcuts are switched off (`actionAllowedInView`) except Escape.


## Discovery Missions

- **Definitions** (`src/data/missions.json`, validated by `missions.schema.json`): each mission has a stable id, title, summary, introduction, recap and 3–5 steps with stable ids. A `find` step names a target (a world or the overview), what to look for, what is revealed and its sources. A `question` step has three answers with stable ids, the correct answer id, a hint, an explanation and sources, and may offer a world to explore. With `visitRequired`, that world must be opened during the step before answers are accepted (used for Saturn and Uranus, so every giant is explored). Every step has a `basis` that tests check against the data: a fact, panel text, a world's kind, solid-surface flags, order from the Sun, a true-scale value from the overview's own calculation, or the scale notes in `src/utils/scale.js`.
- **Independent answer key** (`tests/data/mission-answer-key.js`): hand-written expectations for every step that never read `missions.json`. `tests/data/mission-checks.js` compares each step with the key and the data; mutation tests mark each wrong answer correct and swap revealed facts, and expect failures.
- **State** (`src/features/missions.js`): a pure reducer with per-mission progress (`intro → active → complete`, with a `task`/`feedback` phase per step). Opening a world dispatches `visit`, which only marks the current find step as visited; `found` completes it only after that visit. A `visitRequired` question step also records its visit, and ignores answers until then. `screenKey(state)` identifies the screen being shown (mission, status, step and phase). Correct answers complete a question step; wrong answers are remembered and can't be chosen twice. `next` moves on, and `restart` replays from step 1. Progress is in memory only, and the mission store is separate from the quiz store.
- **Panel and bar** (`src/components/missionPanel.js`): list, intro, task, feedback and recap screens. Steps are labelled “Step n of N”, with “✓ Done” and “You are here” in words. Each task shows its completion criteria. While a mission is unfinished, other panels show a “Back to the mission” bar, which also offers “I’ve found it” on the world the current step is waiting for. Each screen marks one heading with `data-focus-target`; the focused heading's accessible name includes the step result, and the explanation, hint or recap is then read through the polite live region. Explorer shortcuts pause in the missions view except Escape.
- **Reading position:** when the child leaves a mission screen, `explorer.js` saves the focused control and the panel and page scroll positions with that screen's `screenKey`. Returning to the same screen restores them (if exploring unlocked a question's answers, focus starts at the question so Tab reaches the answers next). A different step or screen starts at the top with its heading focused.
- **Delayed announcements:** explanations are read through the live region 300 ms after focus moves. The pending message is cancelled on every navigation and screen change, and it also checks that its quiz or mission screen is still showing before it is read.

## Science Experiments

- **Definitions** (`src/data/experiments.json`, validated by `experiments.schema.json`): the two activities' texts, input limits and units, the gravity lab's planet list (never the Sun), prediction options and source ids. There are no numbers to calculate in the data.
- **Calculations** (`src/utils/experiments.js`): `gravityForceN` (F = m × g), `gravityResult` and `gravityText`, and `tinySolarSystem`, which reuses `trueScaleModel` from `scale.js`. `parseMeasurement` checks typed values (empty, not a number, zero or negative, too small, too big) and returns a friendly message. Results keep full precision; only the `format*` helpers round, for display. Inputs are shown exactly as entered, and `resultSign` picks “=” or “≈” depending on whether the displayed force was rounded. `distanceCategory` gives Neptune's prediction band (under 5 km, 5–10 km, over 10 km).
- **State** (`src/features/experiments.js`): a pure reducer with per-activity settings (`text`, `worldId`, `prediction`), plus `revealed` and `error`. A result appears only after `reveal`. Any later change clears it, so a result never shows values that are no longer on screen. `reset` restores one activity's defaults. The store is separate from the quiz and missions, in memory only.
- **Panel** (`src/components/experimentPanel.js`): the list and activity screens. Inputs are labelled text fields with `inputmode="decimal"`, explicit units, hints and error messages linked by `aria-describedby`. The tiny solar system adds a slider kept in step with the number. Both use the same 0.01 cm precision (the field accepts at most 2 decimal places), and arrow keys move the slider in 0.1 cm steps. Typing, sliding or choosing updates the store without re-rendering, so the cursor never jumps. The panel just hides an out-of-date result. Results label each value as measured or calculated in words. The tiny solar system shows cards rather than a picture.
- **Announcements and focus:** after "Show the result" focus moves to the result heading, and a one-sentence summary is read through the live region. An invalid value moves focus to the field. Reset focuses the heading. Nothing is announced while typing or sliding. Announcements are cancelled on navigation, and they check the experiment screen is still showing. Reading position (focus, panel and page scroll) is saved and restored per view, shared with the missions, using `experimentScreenKey`.

## Navigation, guidance and reliability (Release 1)

- **Activity bar** (`index.html` `nav[aria-label="Activities"]`): Explore, Discovery Missions, Science Experiments and Planet Quiz. `updateControls` sets `aria-current="page"` on the current one. It is shown with fill and a dark bar along the bottom edge, not colour alone. Explore returns to the last world explored, or the overview. On screens up to 640 px the bar is a 2 × 2 grid with short visible names, while screen readers still hear the full names.
- **"Waiting" bars:** the quiz and mission resume bars render only while exploring (overview or a world), never on top of another activity. The activity bar shows progress instead.
- **Help:** a closed-by-default "How to explore" `<details>` under the controls. 3D-only lines carry `data-needs-3d` and are hidden with the 3D controls in the fallback.
- **Reading position:** saved and restored per view for the quiz, missions and experiments (`readingViews` in `explorer.js`). Entering an activity is announced by its focused heading only, while restoring a position announces "Back to …".
- **Reliability:** the scene cancels its animation frame before restarting on every `visibilitychange`, so repeated "visible" events can't start a second loop. Context loss disposes the scene and switches to the fallback. Tests cover failed 3D downloads, no WebGL, and listeners not piling up.

## Planet names and the facts card

- **Names (labels):** each floating name is a button inside a `role="group"` layer over the canvas. Names have `pointer-events: none`, so every tap, drag and pinch reaches the canvas. The scene's own pointer handler decides what a tap means with `pickAt` (`utils/labelLayout.js`): a visible name first, then the world drawn in 3D, then the nearest 44 × 44 px tap area. Only a short, still, one-finger press counts (`isTap`), so drags and pinches never select. Selection goes through the existing `onPick` → `select` action, the same route as tapping a planet.
- **No overlaps:** `placeLabels` puts each name above, below, right or left of its world, in a fixed priority order (a name with keyboard focus first). A name with no free place is hidden for that frame. Hidden names use `hidden`, so they can't be tapped, seen or focused; names are also hidden while a world is chosen or when Labels is off. A ResizeObserver tracks each name's size, so larger text is placed correctly.
- **Keyboard:** visible names are in the tab order, named "Fly to …". Enter or Space selects through the same `onPick`, and focus then moves to the new card's heading, because the name disappears as the camera flies.
- **Facts card:** `sceneCardContent` (in `utils/panelContent.js`) builds the card from existing data and wording: `bodyHeadline`-style kind and place, the Earth width comparison and year length from `earthComparisons` (the Sun's spin instead of a year), and the first of the world's sourced facts that doesn't mention moons or repeat the card. The first sentence of `noSurfaceNotice` is the no-surface line. Each fact is labelled Calculated, Measured · NASA or NASA fact, and the card says the 3D picture is a model. `components/sceneCard.js` renders it into `#scene-card`, an HTML element beside the canvas, so its taps and scrolls never reach the 3D view. `explorer.js` renders it only when the selection changes or a card button is used (never per frame). "Hide card" state resets when a world is chosen. On screens up to 640 px wide, or 520 px tall, it is a strip whose facts open with an `aria-expanded` toggle.
- **Keeping the world visible:** `explorer.js` passes the card's size to `scene.setFrameInset`, which uses a camera view offset so the chosen world sits in the middle of the part of the view the card doesn't cover. While the card column is shown, the "Not to scale" badge moves to the bottom-left.
- **Without 3D:** the same card is shown above the facts panel in the fallback.

## Scientific integrity in code

- **Measurements vs models:** panels label NASA measurements ("Measured · NASA"), values worked out from them ("Calculated") and the 3D view ("Model"). All scale changes are produced by `utils/scale.js` and listed in `SCALE_CHANGES`, which the panels display.
- **No solid surface:** bodies with `hasSolidSurface: false` show a warning, and their gravity and temperature are labelled with the 1-bar level (or photosphere for the Sun). A test fails if any text describes them as having a surface or ground to stand on.
- **Volumes:** Earth comparisons of volume use each planet's volumetric mean radius from its NASA fact sheet, because the giant planets are flattened and cubing their equatorial diameters overstates their volume.
- **Spin direction:** Venus and Uranus spin backwards in the scene because their fact-sheet axis tilt (above 90°) is applied directly. Spin speeds are always positive so the backwards spin is not cancelled out.

## Mobile performance

Touch or small-screen devices get fewer sphere segments, smaller textures (512 × 256), fewer stars, no antialiasing and a pixel ratio capped at 1.5. Textures are drawn by code (no image downloads) one world at a time, and can be turned off with the "Surface detail" button; they start off when the browser asks to save data or the device reports 2 GB of memory or less. The scene only re-renders when something moves, pauses its loop when the tab is hidden, and frees GPU memory on cleanup.

## Accessibility

Every control, including the Simple/Detailed buttons and expandable sections, is a real button or summary with a 44 × 44 pixel minimum target, a visible focus outline and an accessible name. Keyboard shortcuts are listed in the overview panel and ignored while typing or when a focused button should handle Space or Enter. Selection changes are announced through a polite live region. When the panel re-renders, keyboard focus returns to the same Simple/Detailed button (or to the panel), and the world selector only scrolls sideways within its own row, so the page never jumps while someone is reading. `prefers-reduced-motion` starts the explorer paused and makes camera moves instant. A skip link jumps to the facts.

## Tests and CI

Tests live only under `tests/` and mirror `src/`:

- `tests/data/galaxies.test.js`: the Cosmos galaxy collection, checked against the hand-written `galaxy-key.js`. It covers the schema, the approved galaxies, unique ids, names, aliases and catalogue numbers, and source ids with their SCIENCE.md sections. It also checks facts word for word with their supporting quotes, light-year distances with "about" displays, other NASA estimates kept, NED megaparsecs in a sensible range, nearest-first order and the SCIENCE.md distance table. The rest covers J2000 positions, the Milky Way's inside view and illustration, no redshift distances, composite-image notes, WebP sizes and aspect ratios, and an ASSET_CREDITS.md row for every bundled file. See docs/COSMOS_DATA.md.
- `tests/data/missions.test.js`: mission schema and required fields, the three agreed missions with stable ids, valid step references, citations limited to sources the panels already use, coverage by the independent mission answer key, every answer and revealed fact checked against the key and the data, mutation tests, no solid ground for the giants, and no new numbers.
- `tests/data/`: schema, Stage 1 facts preserved, citations, SCIENCE.md tables matching the data, wording rules, superlatives agreeing with the numbers, and quiz questions (schema, unique ids and texts, valid answers, supported and cited answers, no moon counts).
- `tests/utils/`, `tests/features/`, `tests/scenes/`: comparisons, formatting, scale, panel content, navigation, quiz rounds and scoring (uniqueness, shuffling, restart and play again) and appearance.
- `tests/features/missions.test.js`: completion rules (opening a world never completes a step, “I’ve found it” needs a visit during that step, wrong answers don't complete and can't repeat), every mission completing, restart and replay, leaving and switching, announcement wording, and mission and quiz stores staying independent.
- `tests/utils/experiments.test.js`, `tests/data/experiments.test.js`, `tests/features/experiments.test.js`: F = m × g and the scale model against hand-worked examples (10 kg × 9.8 = 98 N, 10 kg × 3.7 = 37 N, the Sun 109.08 cm and Neptune 3,539.5 m with a 1 cm Earth, and others), display-only rounding, invalid, empty, zero, negative and out-of-range inputs, schema and sources, the 1-bar and mass-versus-weight wording, no Sun in the gravity lab, reveal and reset rules, kept settings, and independence from the quiz and missions.
- `tests/e2e/experiments.e2e.js`: completes both activities with guesses, changes and reset, checks validation messages and focus, keyboard-only use (typing digits doesn't trigger shortcuts), no announcements while sliding, no stale announcements, leaving and returning on desktop and phone with focus and reading position, quiz and mission progress kept, 44 × 44 pixel targets and no sideways scrolling on an iPhone and an iPad, and both activities without 3D.
- `tests/e2e/release.e2e.js`: Release 1 regression tests. They cover:
  - the activity bar, its current marker and the phone layout;
  - "waiting" bars only while exploring, and the help with its 2D variant;
  - no sideways scrolling at 200% text, and 44 px source links with unique names;
  - toggle check marks, quiz reading position and single announcements;
  - one animation loop after hide/show, lost graphics, failed or missing 3D, and no listener build-up.
- `tests/utils/labelLayout.test.js`: name placement without overlaps, 44 px tap areas, sides and edges, picking order (name, then world, then nearest tap area) and tap-versus-drag-versus-pinch. `tests/utils/panelContent.test.js` also checks the facts card against hand-written expectations (kind, place, year or spin), reuse of the panel's wording and sourced facts, no moon counts and the no-surface line.
- `tests/e2e/sceneLabels.e2e.js`: touch taps on every visible name on an iPad, no overlapping names on a phone, hidden names neither focusable nor shown, keyboard selection with focus on the card, drags and pinches from a name turning the view without selecting or scrolling the page, the card's content and buttons (hide/show, another planet, More facts focus, Solar system), taps and drags on the card not reaching the 3D view, phone strip, iPad layouts at 200% text, reduced motion, 2D, and quiz progress kept.

The single CI job runs install → lint → unit tests → build → browser tests on every pull request and push to `main`. A dependent job deploys `dist/` to GitHub Pages from `main` only. Vite uses a relative asset base for the Pages repository path.
