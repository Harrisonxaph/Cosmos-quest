# Contributor and agent instructions

Build a child-friendly solar system explorer with accurate, traceable facts.

- This file is authoritative; agent.md only points here.
- Keep scientific content in `src/data/`: planets in `planets.json`, the Sun in `sun.json`, both validated against `planets.schema.json` (the Sun uses `definitions/body`). Every fact, text block, measurement and moon count cites source ids listed in `src/data/sources.json`, each with a matching heading and link in `docs/SCIENCE.md`. Facts must appear word for word under their source, and the SCIENCE.md tables must match the data; tests enforce both.
- Use NASA or ESA primary sources. Date volatile values such as moon counts and say when NASA pages disagree. Extend the sourceId pattern, schema and tests together if adding ESA sources.
- Never describe Jupiter, Saturn, Uranus, Neptune or the Sun as having a solid surface or ground to stand on. Give their gravity and temperature at the 1-bar level (photosphere for the Sun) and say so.
- Keep measurements, calculated comparisons and the illustrative 3D model clearly separated and labelled. All scale changes go through `src/utils/scale.js` and must be listed in `SCALE_CHANGES`. Keep the real order of sizes and distances.
- Keep the Stage 1 planet facts unchanged as each planet's first fact.
- Keep tests under `tests/`, mirroring `src/`. Browser tests go in `tests/e2e/`. Do not mix in colocated tests.
- Record every bundled asset file and its verified licence in docs/ASSET_CREDITS.md. Never assume NASA or ESA credit implies permission. Procedural textures are generated in code and are not NASA imagery.
- Keep shared UI in components/, 3D orchestration in scenes/ (the only folder that imports Three.js), user capabilities and navigation in features/, reusable hooks in hooks/ when a hook-based framework is introduced, and pure helpers in utils/. `scenes/appearance.js` holds illustrative looks, never science.
- Preserve keyboard access, readable text, reduced-motion support, 44-pixel touch targets, the 2D fallback and mobile performance settings as features are added.
- Use Node 24 and npm ci. Before submitting changes run npm run lint, npm test, npm run build and npm run test:e2e. Commit package-lock.json. Three.js is pinned to an exact version.
- Galaxy data for the Cosmos view lives in `src/data/galaxies.json` (validated by `galaxies.schema.json`), with images in `public/assets/galaxies/`. Follow docs/COSMOS_DATA.md: cite NASA pages only, use NED as a cross-check, keep other estimates instead of combining them, label the Milky Way image as an illustration, and update the hand-written `tests/data/galaxy-key.js` by hand.
- Do not select galaxy distances by proximity to NED's median or treat its range as an uncertainty interval. Preserve `estimateNote` and review flags, and keep showing each `estimateNote` beside its distance. Before marking an image ready, verify its source caption and specific terms separately in `image.permission`; show full credits, active source/terms links and modification notices with every picture. A NASA/ESA credit alone is not permission. Keep UV captions child-friendly.
- Quiz questions live in `src/data/quiz.json`, validated by `quiz.schema.json`. Each has three answers with stable ids, a `basis` pointing at a fact, panel text, measurement or ranking the app already shows, and source ids already used by the information panels. Do not ask about moon counts or anything ambiguous. Every new question also needs a hand-written entry in `tests/data/quiz-answer-key.js`; never derive that key from `quiz.json`. Quiz state and scoring stay in `src/features/quiz.js`, separate from `src/components/quizPanel.js`. Keep quiz progress in memory only.
- Discovery Missions live in `src/data/missions.json`, validated by `missions.schema.json`. Keep mission and step ids stable. Every step needs a `basis` the tests can check against the data and source ids already used by the information panels; add no new numerical claims. Every new step also needs a hand-written entry in `tests/data/mission-answer-key.js`; never derive it from `missions.json`. Opening a world must never complete a step by itself: completion needs “I’ve found it” after a visit, or a correct answer (after the required visit for `visitRequired` questions). Preserve the saved reading position when returning to the same mission screen, and keep delayed announcements cancellable. Mission state stays in `src/features/missions.js`, separate from `src/components/missionPanel.js` and from quiz progress, in memory only.
- Science Experiments live in `src/data/experiments.json` (validated by `experiments.schema.json`), with pure calculations in `src/utils/experiments.js`, state in `src/features/experiments.js` and rendering in `src/components/experimentPanel.js`. Use only measured values from `src/data/`, keep full precision and round only for display, and document formulas, assumptions, units and rounding in docs/SCIENCE.md. Weight is a force in newtons; never give it in kilograms or suggest mass changes. Exclude the Sun from the gravity lab and name the 1-bar level for the giants. Results appear only after a deliberate action; never announce on every keystroke or slider movement. Keep experiment settings in memory, separate from quiz and mission progress.
- Cosmos (the galaxy map in Explore) follows docs/COSMOS_FEASIBILITY.md option 2: keep the map illustrative and labelled not to scale, keep the order of distances, never imply that sky closeness or zoom means closeness in space, keep every galaxy reachable from the list if the map fails, keep map gestures on the map only, and add no live catalogue requests or Three.js to it. Layout rules stay in `src/utils/cosmosLayout.js` with `COSMOS_SCALE_NOTES`; map state in `src/features/cosmos.js`.
- Stages 2 to 5 are complete, and Release 1 (usability, accessibility and reliability) is a candidate. Keep the activity bar's current marker, the "waiting" bars only while exploring, the How to explore help (3D-only lines marked `data-needs-3d`), per-view reading positions and single announcements. Add new critical journeys to `tests/e2e/journeys.e2e.js` so they also run in WebKit, and keep docs/RELEASE_CHECKLIST.md current. Do not add further experiments, badges, rewards, audio, timers, persistent progress or offline caching until they are agreed.
- Do not commit credentials or add analytics, accounts, or paid services without an explicit requirement.
